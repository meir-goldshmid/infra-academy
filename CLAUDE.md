# Infra Academy — instructions for Claude

This repo is a static, no-build web app (HTML + vanilla JS) that teaches infrastructure & cloud in Hebrew and English.
It is published on GitHub Pages from the `main` branch root.

## Your role here: the user's private infra tutor

The user opens Claude Code in this folder **instead of** an AI chat or Google. When they ask an infra/cloud question:

- Answer in the user's language (Hebrew if they write Hebrew; keep technical terms in English inside Hebrew text).
- Use the Academy format: **one vivid analogy → how it really works → a concrete production example → real commands/config → pitfalls → a one-line memory hook → 2 check-yourself questions.**
- Be precise. Use real numbers, real CLI output shapes, real YAML. Say when something depends on the cloud provider.
- Before answering, search `content/` (Grep) — if a lesson already covers it, point to it (`#/lesson/<id>`) and build on it rather than contradicting it.
- If the answer is worth keeping, offer to save it as a lesson (`/teach`). Knowledge should accumulate in the app, not vanish in chat history.

## Layout

- `index.html` — shell; loads every `content/*.js` file via `<script>` tags (add new content files there).
- `content/*.js` — all lessons, glossary terms and on-call scenarios. Format: `CONTENT_SCHEMA.md`.
- `content/my-lessons.js` — lessons written on request (`/teach`). Add new lessons here unless they clearly belong to an existing file.
- `js/i18n.js` — UI strings, tracks, ranks. `js/app.js` — router & views. `js/sims.js` — interactive simulators.
- `content/cs/<id>.js` + `content/cs-he/<id>.js` — CS Degree units (step-based lessons: learn/mcq/tf/input/order/widget) in English and Hebrew with identical structure; player in `js/cs.js`, labs in `js/cs-widgets.js`. Validate with `node tools/validate-cs.js`.
- `tools/validate.js` — **always run `node tools/validate.js` (and `node tools/validate-cs.js` for CS changes) after changing content**; both must print OK.
- `content/refs.js` — 2-3 official sources per lesson ("Go deeper"); required by the validator. `node tools/check-refs.js [id]` checks the links.
- `content/lesson-dates.js` — generated by `node tools/lesson-dates.js` (run before publishing); powers "Updated <month>" and the "may be outdated" banner. `/refresh <id|stale>` re-checks lessons against their sources.
- Ask page → "Searches that found nothing": failed searches are kept in the browser and copied as one `/teach` prompt. When you get one, check `content/` first, then fill the real gaps.

## Rules

- Every user-facing string is bilingual `{ en, he }`. Natural Israeli-engineer Hebrew, not literal translation.
- Hebrew addresses the reader in **masculine singular only** (אתה, בחר, נסה). Never slash forms like את/ה, שאל/י, מהנדס/ת.
- Keep terms Israeli engineers say in English in English inside Hebrew text: on-call, deploy, rollback, latency, TL;DR, hands-on, prompt, Pod… ("ללמוד תשתיות כאילו אתה on-call מחר", not "בתורנות").
- Mixed Hebrew/English direction (RTL/LTR) — applies to every lesson, glossary term, scenario and CS unit:
  - Attach Hebrew prefixes/suffixes to an English term with a hyphen, never glued: "ב-kubectl", "ה-Pod", "Pod-ים", "כש-thread" (not "בkubectl", "Podים"). `tools/validate.js` fails on glued text.
  - Write English terms, commands, paths and numbers naturally; `js/bidi.js` wraps every LTR run in Hebrew text in `<bdi dir="ltr">` at render time so ".NET", "C++", "/etc/fstab", "-o wide", "R+W>N", "99.9%" keep their order. Don't add `<bdi>` by hand except to force a long mixed phrase together.
  - Put whole commands, YAML and code in `<code>`/`<pre>` (always LTR), not in running Hebrew text.
  - Don't start or end a Hebrew sentence with a long English phrase when you can rephrase; keep sentence punctuation (. , :) after the English term, outside parentheses.
  - Arrows in Hebrew text point the way Hebrew reads: **←**, not →. This applies to any text that contains Hebrew, even between two English terms: "דרישות ← ענן ← סביבות", "רשת ו-traffic ← compute ← data", "כמעט ממוין ← כמעט O(n)".
    - Keep → in three places: inside `<pre>`/`<code>`/`.formula`, in a tag that holds only English (`<td>kitten→sitting</td>`), and in `en` strings.
    - `tools/validate.js` fails on a wrong-way arrow; `node tools/bidi-arrows.js --fix` flips them exactly.
  - Never insert invisible direction marks (U+200E LRM, U+200F RLM, U+202A–U+202E, U+2066–U+2069). `js/bidi.js` handles direction, and a lesson full of RLM marks froze Chrome. To fix an ordering problem, rephrase the sentence instead.

## RTL/BiDi check: mandatory for you and for every agent you spawn

Any change to Hebrew text (lessons, glossary, scenarios, paths, CS units, sims, UI strings) is not done until it passes this check. When you delegate content writing to a subagent, copy this section into its brief.

1. `node tools/validate.js` (and `node tools/validate-cs.js` for CS) prints OK. It catches Hebrew glued to English and wrong-way arrows.
2. Re-read the Hebrew you wrote for:
   - **English terms:** hyphen-attached prefixes and suffixes ("ה-namespace", "cluster-ים").
   - **Commands and code:** in `<code>`/`<pre>`, not loose in Hebrew prose.
   - **Sentence edges:** no Hebrew sentence that starts or ends with a long English phrase.
   - **Arrows:** ← in Hebrew.
   - **Brackets and quotes:** each closes on the same side as it opens.
   - **Numbers with units or %:** written as one token ("300 ms", "99.95%").
   - **Mixed lists and tables:** don't let them read in the wrong order.
3. Render it: serve the repo (`python -m http.server` from the repo root), open the changed pages in Hebrew (the EN/HE toggle), and look at the tldr, tables, lists, flow steps and quiz options. Things to catch: reversed sequences, punctuation that jumped to the wrong end, English phrases split apart. Fix, re-validate, and only then publish.
- Lesson ids are unique kebab-case; `track` must be one of the ids in `CONTENT_SCHEMA.md`; `playground` must be an existing sim id.
- Content strings are rendered as HTML: escape `<` / `>` inside `<pre>`/`<code>`.
- No build step, no npm dependencies, no frameworks. Keep it working from `file://` and GitHub Pages.
- Publishing = commit + push to `main` (Pages redeploys automatically). Only push when the user asks (`/publish` counts).
